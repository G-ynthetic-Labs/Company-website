Platform · Verifiable Inference

Replay any AI answer. Get the same bytes.

When an expert signs off on what a local model produced, that sign-off should stay true. Verifiable Inference replays a past answer and returns identical bytes, or returns nothing, and its ledger catches an environment that drifts over time.

Talk to usPart of the engine
How it works

Witness, ledger, verify.

Frozen settings

Sampling is fixed, and a warm-up call is made and discarded.

A witness call

A second call must match the first byte for byte, or nothing is returned.

Into the ledger

A hash-chained ledger holds the fingerprints, never the text.

Verify any time

Replay later; a drifting environment shows up as a mismatch.

What you get
  • Attest anything, not just model output: documents, build outputs, datasets and model files.
  • A code-free command line for shells and build pipelines: attest, verify, check the ledger.
  • Accountability hooks to veto before generation, add witnesses or publish the ledger head, none of which can alter the bytes.
  • A peer-review command with six falsification checks and evidence a reviewer can recompute.
  • Zero runtime dependencies and 54 tests.
Reproducibility, not correctness

What it proves, and what it doesn't.

  • It proves an answer is the same answer. It does not prove the answer is right; that is the expert's job.
  • It works with a local model on fixed hardware. A hosted model service voids the guarantee.
  • Witnessing costs about three times the latency while it is on.
Who it's for

Teams whose AI output has to hold up later.

Expert sign-off

Work where a qualified person validates output, and that validation has to stay provable.

Audit-heavy work

Anywhere you may need to show months later exactly what a system produced.

Unchanged artifacts

Show that a document, build, dataset or model file has not changed since it was approved.
